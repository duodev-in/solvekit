# Tool UI Decisions

Every calculator page (Conversion Tools, Biology & Nature, Chemistry, Construction, Ecology, Everyday Life, Finance, Food and Cooking, Health and Math) uses one layout, "Design A (Split Panel)". Build new tools with the same components; do not hand-roll page markup.

## Page frame

- Wrap every tool in `<x-calc.page>` (`resources/views/components/calc/page.blade.php`). It renders breadcrumbs, title and lede, structured data, ads and the related-tools card from `App\Services\CalculatorCatalog`; do not add these by hand.
- Left panel: inputs, then `<x-calc.result>` directly after them, then `<x-calc.options>` (decimals, example chips, reset).
- Right panel (`<x-slot:panel>`): the supporting results only, as `<x-calc.rows>`, `<x-calc.quick-ref>`, `<x-calc.unit-list>` or `<x-calc.grid>`.
- Below both panels: the How it works / Formula / FAQ tabs (from `about`, `how-to`, `faqs` and `<x-slot:formula>`) and the Related tools card, shown at full height. Page scrolling here is fine.
- Desktop splits the panels 7fr / 5fr; phones stack them in the same order.
- Do not add a "How it was worked out" panel to the right side; the How it works and Formula tabs already explain the calculation.

## Components

- Inputs: `x-calc.field` (number, text or date), `x-calc.select`, `x-calc.segmented`, `x-calc.unit-pair`, `x-calc.textarea` (sequences, lists), `x-calc.substance`, `x-calc.checkbox`.
- `x-calc.shape` is the plan-shape menu with a small diagram (rectangle, circle, triangle, trapezoid, L-shape, ring, oval); its fields are `length`, `width`, `diameter`, `base`, `height`, `side_a`, `side_b`, `cut_length`, `cut_width`, `outer`, `inner`, read by `shapeArea()` in `resources/js/calc/construction/geometry.js`.
- `x-calc.grid :scroll="true"` caps long tables (loan and savings schedules) at a fixed height with their own scroll.
- `x-calc.rows-editor` holds a list of rows (rooms, walls, pieces) in a hidden textarea, one row per line; give it a unit family and pass the same units to the page as `rowUnits` so the handler can convert them. Columns listed in `:text` are free text (names, clock times) and switch the stored separator to tabs; read rows with `parseRows()` from `resources/js/calc/rows-editor.js`. `:lists` gives a text column a searchable list of suggestions (ingredient names, units) without restricting what can be typed. Example chips set it like any field.
- Results: `x-calc.result`, `x-calc.rows` (fixed labelled values), `x-calc.quick-ref` (lists the script fills), `x-calc.unit-list`, `x-calc.grid` (Punnett squares and other tables; a row with `highlight: true` marks the table entry that matches the result), `x-calc.plot` (SVG line charts drawn by the script; no chart library).
- Use `data-show-when="field:value1,value2"` to show inputs only for the mode that uses them, rather than separate pages or custom script.
- `x-calc.steps` is the monospace Working panel filled from the handler's `texts.steps` (one line per step; aligned columns such as long division and bit patterns keep their spacing). `x-calc.plot` also draws `kind: 'diagram'` (shapes, dots and labels drawn to scale, for geometry and Argand diagrams) and `kind: 'numberline'` (intervals with open and closed ends); line charts accept `scatter`, `extra` dashed series, `axes` and NaN gaps between branches.
- Long `x-calc.rows` and `x-calc.unit-list` lists collapse to 4 rows below 1024px. Long generated lists use `x-calc.quick-ref :collapse="true"`, which shows 8 rows and a "Show all" button at every width.
- Every select with a default must mark it with `@selected`; config order is not a default.

## Scripts and data

- Pages pass a `calc` config to the shared runtime (`resources/js/calc/core.js`). Pick an engine in `resources/js/calc/engines/` (`units`, `substance`, `number-scale`, `radix`, `geo`, `formula`) instead of writing page scripts.
- Formula tools are pure handlers in `resources/js/calc/tools/*.js` returning `{ value, unit, label, sub, rows, lists, grids }`, or `{ empty }` / `{ error }`. Cover new handlers with unit tests in `resources/js/calc/tests/`.
- Keep reference data in config (`config/units.php`, `config/biology_data.php`, `config/elements.php`, `config/chemistry_data.php`, `config/construction_data.php`, `config/ecology_data.php`, `config/everyday_data.php`, `config/finance_data.php`, `config/food_data.php`, `config/physics_data.php`, `config/sports_data.php`, `config/statistics_data.php`), never in views or scripts, and cite its source in a comment. Take values from a published source rather than typing them from memory, and do not extrapolate data outside its stated range.
- Register tools in `config/conversion.php`, `config/biology.php`, `config/chemistry.php`, `config/construction.php`, `config/ecology.php`, `config/everyday.php`, `config/finance.php`, `config/food.php`, `config/health.php`, `config/math.php`, `config/physics.php`, `config/sports.php` or `config/statistics.php`, and add a new section to `CalculatorCatalog::SECTIONS` and `routes/web.php` (pass a URL prefix as the third argument when it differs from the config name, as `everyday-life` does). A category's `elsewhere` entries link to a tool that already lives in another section instead of repeating it. Routes, navigation, breadcrumbs, related tools and the section index are derived from there.

## Results and content

- Keep result typography capped and let long values (sequences, dates) wrap rather than shrink or overflow; values over 26 characters (dates, converted text) switch to a smaller size automatically.
- Format money as `$1,234` in the value, not as a trailing unit, through `formatMoney()` in `resources/js/calc/currency.js` (or the section helpers built on it), never a hard-coded `$` or `Intl` with `currency: 'USD'`.
- Every page that shows money lets the viewer choose the currency (51 currencies including the Indian rupee, listed in `config/currencies.php` and `currency.js`, kept in step by a test). Give money fields `suffix="$"` (or `$/kWh` and similar); the runtime swaps the `$` for the chosen symbol and shows the Currency menu in the options bar. The choice is remembered in the browser. Amounts are not converted, only labelled, and rupees use lakh/crore grouping.
- Pages whose figures follow one country's law or data (US tax and payroll, IRS limits, UK tax, Indian schemes, US coins) set `'currency' => 'USD'` (or the country's code) with `'currencyFixed' => true`, which hides the menu. A page may set a different default with `'currency'` alone (EMI calculators default to INR).
- Every default and example chip must give a real result. When a value is an estimate or a rule of thumb, say so in the result or the About text.
- Do not build veterinary medication-dose or toxicity calculators: their outputs would be clinical recommendations from ranges.
- Code-based answers (IRC, NEC, ADA, OSHA, AWS) cite the section and say local codes may differ; do not build structural sizing tools (beam, joist, header, snow or fire-flow design) that would stand in for an engineer.
- Rows that only apply to one mode go in their own `x-calc.rows` block wrapped in `data-show-when`, so no visible row is left empty.
- Footprint figures come from a named, dated public dataset stored once in config; show the source and year on the page and let the viewer replace any factor. Large lookup lists (airports) live in `public/data/` and are fetched only by the page that needs them.
- Dates and times use the civil-calendar helpers in `resources/js/calc/everyday/dates.js` (day numbers, never `Date` arithmetic), so results do not shift with time zones or daylight saving; say so when a tool ignores daylight saving. Tools that need the current moment read it once through `nowCivil()` and accept a `now` input in tests.
- Size charts and rules of thumb (shoe, bra, tie, desk heights, balloon spacing) are labelled as conventions with the formula shown; where no common standard exists (dress or swimwear sizes), do not build the tool.
- Finance tools use the helpers in `resources/js/calc/finance/` (`money()`, `pct()`, `num()`, `yearGrid()`; TVM and loan engines). Percent fields are entered as percentages and divided by 100 in the handler. Every Finance page states that results are estimates for planning, not financial, tax or legal advice.
- Tax, limit and rate tables (federal and state brackets, FICA, IRS limits, UK, India, other countries) live once in `config/finance_data.php` with their source and year; pages read them through `data_keys` and show the year. Prices that change daily (metal spot prices, exchange rates, ad RPM) are entered by the viewer, never stored.
- One-formula Finance tools are entries in the `TOOLS` table of `resources/js/calc/tools/fin-simple.js` (inputs with their kind, the result formula, extra rows and the formula text for the "With your numbers" row); change a tool by editing its entry.
- Food and Cooking tools measure with `resources/js/calc/food/kitchen.js`: US (236.6 ml), nutrition-label (240 ml), metric (250 ml) and imperial cups, US, metric (15 ml) and Australian (20 ml) tablespoons, and volume-to-weight by ingredient from the USDA household measures in `config/food_data.php`. Never type a density or calorie value into a handler; add the ingredient to the data instead. Write measures with `measure()` (kitchen fractions such as 1⅓ cups) and recipe lists as rows of amount, unit and ingredient read with `parseAmount()`, `parseUnit()` and `findIngredient()`.
- Cooking times, thawing and storage come from USDA FSIS tables (turkey timetable, ham chart, safe minimum temperatures, FoodKeeper) and every such page says to check with a food thermometer; caffeine, calorie and curing pages cite FDA, AHA, EFSA or USDA and give no medical advice. Party amounts, brew ratios and similar kitchen rules are labelled as conventions and are editable on the page.
- Health tools never calculate a medicine dose, infusion order or treatment plan (no pediatric or adult dosage, insulin, warfarin, transfusion or maintenance-fluid calculators). Deficit and rate formulas (bicarbonate, free water, sodium, Ganzoni iron, Parkland) say they are estimates for teaching and that the treating team decides. Schedules (half-life, three times a day, refills) only do time and date arithmetic on the user's own instructions. Every Health page carries "For information and education, not a diagnosis or medical advice." through `hd()`.
- Published scores and questionnaires are data, not code: items, points, bands and the source live in `config/health_data.php` under `scores.{key}` and render through the `score` handler in `tools/hl-scores.js`. Use the authors' wording and cut-offs; questionnaires with a self-harm item (PHQ-9, EPDS) define an `alerts` entry that shows crisis lines (988, Samaritans 116 123, Tele-MANAS 14416).
- Lab values with more than one unit use a `{name}_unit` select and are converted to conventional US units with `toConventional()` from `resources/js/calc/health/labs.js`; add an analyte there instead of converting inside a handler. Risk equations (Pooled Cohort, Framingham, KFRE, MELD 3.0, CKD-EPI 2021) use the published coefficients, state their valid age range and show the source; do not build risk models whose coefficients are not public or that need tumour pathology.
- Math tools keep answers exact wherever the maths allows: read typed numbers with `q()` from `resources/js/calc/math/util.js` (fractions, mixed numbers, repeating decimals), compute with the BigInt rationals in `math/rational.js`, show roots with `surd()` and give a decimal beside them. Floating point is only for genuinely numeric work (eigenvalues, SVD, special functions, integrals), and those results show a residual or check. Every Math handler returns its working through `result()` so the Working panel never shows a previous answer.
- Shapes are data in `math/shapes.js`: a shape lists its quantities, the sets of known values it can be solved from (`cases`) and how every quantity follows (`all`), plus a scale drawing. Add a shape there and give the page `'shape'`/`'want'` config for the generic `shape` handler instead of writing a page handler. Lengths are plain numbers with a Unit select; areas and volumes are shown in that unit squared or cubed with conversions.
- Exact trig values come from the table in `tools/mt-trig.js` (multiples of 15°, 18° and 22.5°), checked against the computed value by a test. Identity checks are numerical (many unrelated angles), and the page says so.
- Practice mode (`with_practice` in the generator, `math/practice.js`) adds a Mode select, seeded questions by question number, an answer check and the worked answer, with its rows in their own `data-show-when="mode:practice"` block.
- Physics tools are definitions in the `TOOLS` tables of `resources/js/calc/tools/ph-*.js`, run by `resources/js/calc/physics/core.js`: a `law` (one equation, the page picks what to solve for, every other quantity keeps its own unit menu; build power laws with `pw()`) or a `calc` (inputs, `run(v, ctx)` returning SI numbers or text). Inputs arrive in each unit table's base and are converted to SI (mass g → kg, volume L → m³, temperature °C → K); results are shown in the unit picked, and rows in a metric step that reads well (47.1 MPa, not 47,082,000 Pa) with the common imperial alternative. Constants come from `K` (CODATA 2018; c, h, e, k and Nₐ exact).
- Physics reference data (planets, refractive indices, materials, fluids, gases, conductors, nuclides and more) lives in `config/physics_data.php` with its source; a select lists a table with `'data:table'` (adding an "Other" choice with typed values) or `'data:table:fixed'`. Water, moist air and the standard atmosphere use `physics/air.js` (IAPWS-IF97, Kell, Hyland–Wexler, US Standard Atmosphere 1976); the sun uses `physics/sun.js` (NOAA/Meeus). Engineering rules of thumb (arrow speed, quarter mile, exhaust size, speeds and feeds, Peukert) are labelled as estimates; Wind Load is a physics estimate, not a design load. Tools whose only method is proprietary charts or coefficients not stored here (refrigerant capillary sizing, magnetic declination, motor capacitor rules of thumb) are not built.
- Sports tools (`resources/js/calc/tools/sp-*.js`) run on the Physics engine and read `config/sports_data.php` through `ctx.c.data.sports`. Official statistics follow each sport's own definition (innings as 6.1 = 6⅓, overs as 12.3 = 12 overs 3 balls); training numbers use a named published formula (Compendium METs, ACSM, Daniels' VDOT, Riegel, Coggan, Friel, World Athletics tables) and say so in the working. Times are typed as h:mm:ss text and parsed with `sports/time.js`. A select can list chosen rows of a table with `'data:table:fixed:key1,key2'`. Tools that need tables not stored here (DLS, DIN release charts, WMA age grading) are not built.
- Statistics tools (`resources/js/calc/tools/st-*.js`) run on the Physics engine with the numerics in `resources/js/calc/statistics/`: `special.js` (incomplete gamma and beta, inverse normal AS 241, noncentral t AS 243), `dist.js`, `data.js`, `tests.js` and `reg.js` (QR least squares). New numerical code is checked against SciPy or R before it ships; never type reference values from memory. Follow R’s conventions (Welch t by default, exact rank tests for small untied samples, Fisher’s two-sided rule). Where textbooks differ (quartile methods, sample vs population, skewness forms) offer the choice and name it in the working. Random tools use the browser’s cryptographic source; paradox simulations are seeded so a run repeats. Charts: `plots` accept `bars` (with `categories`), `areas` (shaded regions), `kind: 'box' | 'pie' | 'venn'`; colour classes must be written literally in JS so Tailwind keeps them.
